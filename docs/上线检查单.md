## 四、nginx Accept 区分验收(Phase 7 终审钉子——同一 /s/{token} 路径双解析)

对**同一** `TOKEN`(真实分享 token)执行两条命令:

```bash
# ① 浏览器导航(Accept 含 text/html)→ 必须回 SPA index.html,由前端路由 /s/:token 渲染分享页
curl -si -H 'Accept: text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8' \
  https://<host>/s/$TOKEN | head -8          # 期望:200 + text/html + <!doctype html>

# ② 页内 fetch JSON(ShareView rawRequest,fetch 默认 Accept: */*)→ 必须放行上游返回 JSON 快照
curl -si -H 'Accept: */*' https://<host>/s/$TOKEN | head -8
# 期望:200 + application/json + {"code":"OK","data":{"title":...,"nodes":[...]}}
```

## 七、生产部署步骤(构建 → 配置 env → up → Flyway 自动 → 验收)

```bash
# 0. 服务器准备:4C8G 云主机 + Docker Engine ≥ 24(compose v2);放行 80(工作台 8081 仅内网)
# 1. 构建(任一机器,产物随仓库目录上服务器)
./mvnw -B -ntp -DskipTests package          # 后端 jar → ke-boot/target/ke-boot-0.1.0-SNAPSHOT.jar
bash ops/build-frontend.sh                  # 前端 dist → frontend/dist/{explorer,workbench}
# 2. 配置 env(服务器部署目录 .env,compose 自动读取;勿提交入库)
cat > .env <<'EOF'
KE_JWT_SECRET=<openssl rand -base64 48 生成,≥32 字节>
KE_PG_PASSWORD=<强口令>
KE_REDIS_PASSWORD=<强口令>
KE_LLM_API_KEY=<DeepSeek key>
# 可选:KE_LLM_BASE_URL / KE_LLM_GENERATOR / KE_LLM_ROUTER / KE_DB_USER / KE_SMS_*
EOF
chmod 600 .env
# 3. 启动(Flyway 在 app 启动时自动迁移;首次拉镜像较慢)
docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml ps          # 等 5 容器 healthy(start_period 最长 90s)
docker compose -f docker-compose.prod.yml logs app | grep -i flyway   # 确认迁移执行
# 4. 验收:跑本检查单第三、四节全部命令(健康/swagger 404//s/ 双解析/限流);
#    内测冒烟:注册登录→建会话→讲解→整理→分享打开→接续
# 5. 备份:配置 cron 接入 ops/backup.sh,并完成第五节恢复演练
# 回滚:上一版 jar/dist 就地替换后 docker compose -f docker-compose.prod.yml up -d;
#       DB 不可回滚时,恢复最近备份(ops/restore.sh)并回退应用版本
```
