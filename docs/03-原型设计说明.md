# 03 原型设计说明

> 两个原型均为**单文件、零依赖 HTML**，直接用浏览器打开即可（建议 Chrome/Edge，移动端原型内置 393×852 手机框架）。
> 原型目的：在写代码之前，把一期 MVP 的交互闭环和分期边界"讲清楚、点得到"，用于评审与开发对齐，不是视觉稿。

```bash
cd knowledge-explorer-design/prototype && python3 -m http.server 8080
# http://127.0.0.1:8080/index.html      移动探索端
# http://127.0.0.1:8080/workbench.html  创作/运营工作台
```

### 1.2 建议体验路径（对应一期验收 A1–A5）

1. **首页 → 岳麓书院** → 点入口"为什么建在这里" → 自动经历"执行中"→ 讲解卡（A1：有出处的有效深入）
2. 讲解卡 → "看看与选址相关的人物" → 人物卡 → 时间线（连续探索）
3. 点顶部 🧭 → **路径树已记录你的轨迹** → 点"岳麓书院（起点）"回到该节点 → 再点任一入口 → 回到路径页可见**新分支标记**（A2）
4. 卡片页底部 → "✚ 用一句话新增入口" → 生成配置 → 试运行 → 保存到个人空间（A3）
5. 路径页 → "整理目前发现" → 勾选分支发现 → 去分享 → 生成链接 → **接收者视角**（快照+沿此路径继续=副本）（A4/A5）
6. 首页 → 湘菜风物 → 对比卡 → 跨主题进入声音科学（验证"跨主题关联必须说明关系"）

### 1.3 关键设计规则（从方案落到界面）

- **路径常驻**：每个二级页面顶部都有 🧭 入口，"来路与返回"永远可见（方案 §3 页面与导航）。
- **入口数量纪律**：默认 5 个，其余收起；"新增入口"永远是列表末尾的虚线按钮。
- **三档可信标识**：📎事实（绿）/ ✦归纳（蓝）/ ✦创意生成（橙），讲解卡和任务卡都带；出处角标全文统一 `[n]` 样式。
- **停顿设计**：路径页底部三键"整理发现 / 暂存 / 换个方向"（方案"让持续探索可以停下来"）。
- **分期可见**：二期地图卡、三期互动组件在原型中明确标注"二期/三期"，让评审者看到边界而非空白。

## 2. 创作/运营工作台（workbench.html）

| 模块 | 对应需求 | 演示要点 |
|------|---------|---------|
| 卡片管理 | FR-C07/C08 | 状态筛选、模板标识（含二期/三期模板的灰态展示）、详情抽屉：**版本历史不可变**、被入口/路径引用统计、停用影响提示 |
| 入口编排 | FR-N01–N07 | 四步流程条（一句话→配置→试运行→发布）；**白名单意图说明**；资料范围输入框禁用（🔒不可用自然语言扩权）；已有入口表：版本、使用量、试运行合格率（对应指标"入口成功率"） |
| 审核中心 | FR-O03 | 待审卡片/入口/反馈三个队列；机器预检标签（出处有效/无越权/敏感词）+ 人工通过/驳回；"发布后通知入口作者重测"的影响提示 |
| 知识资源 | FR-O01/O02 | 知识单元定位信息（卷/章/页/时间戳）、授权状态与**到期续期机制**、被引用次数（来源完整率的数据基础） |
| 数据看板 | FR-O05 | 方案第九章 6 指标逐项落地+专题速览+成本时延（"服务成本与时延"直接展示 ¥/次） |

## 3. 原型验证目标（评审时要回答的问题）

| # | 问题 | 在哪个界面验证 |
|---|------|--------------|
| Q1 | 入口文案能否让用户预判点击后得到什么？ | 界面 2（入口行"类型+方向"副标题） |
| Q2 | 事实/归纳/生成三档标识是否可被普通用户理解？ | 界面 4、12 |
| Q3 | 路径树+分支的呈现是否解释了"回到节点=新分支"？ | 界面 15（含引导提示条） |
| Q4 | 一句话新增入口的"配置草稿+锁定范围"是否降低了失控感？ | 界面 13、14 |
| Q5 | 接收者视角"如何发现+发现了什么"的信息层次是否成立？ | 界面 18 |
| Q6 | 编辑能否在 3 步内完成一次审核？ | 工作台·审核中心 |
| Q7 | 分期边界（二期/三期功能灰态标注）是否清晰？ | 界面 2/10、工作台·卡片管理 |

## 4. 已知取舍

- 原型为纯前端静态模拟：服务执行 2 秒后自动跳转结果页，真实实现为轮询（见 02 文档 §5.1）。
- 路径树为内存数据、刷新重置；真实实现为 `path_node` 服务端持久化。
- 视觉采用轻量 CSS 还原布局与信息层级，正式 UI 规范已另行产出：见 `04-主题与UI规范.md` 与 `prototype/styleguide.html`（沿用"靛蓝主色+三档可信色"的信息色系统，并修正了原型中对比度不达标与语义撞色的取值）。
